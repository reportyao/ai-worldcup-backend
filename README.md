# 球多多 AI 足球预测 - 后端服务

## 项目简介

这是“球多多 AI 足球预测”平台的核心后端服务，负责承载用户前端、管理后台、预测生产线、数据同步、权益订单、赛后复盘与模型评估等关键能力。后端以 **NestJS + Prisma + BullMQ** 为主体架构，通过 API 服务对外提供统一接口，通过 Worker 服务执行足球数据同步、特征计算、AI 预测生成、共识聚合、赛后评分和复盘生成等异步任务。

近期已增强了 **Lindy AI 预测闭环、竞彩自动化同步、预测历史对照与结构化人工复核** 能力。系统现在能够在固定北京时间自动读取竞彩数据、每天统一触发 Lindy 预测、准确区分等待回调与失败状态，并在预测对照中直接使用结构化结果进行展示和编辑。

## 核心能力：全自动化闭环系统

本项目已实现完整的自动化运行闭环，无需人工干预即可完成从数据抓取到 AI 预测再到结果统计的全过程。

| 能力 | 当前实现 |
| --- | --- |
| **定时自动抓取** | 集成中国竞彩网（Sporttery）数据源，Worker 按固定北京时间自动抓取销售日期、比赛双方、盘口及赛果。默认同步时间为北京时间 **03:00、05:00、10:00、10:30、11:00、15:00、24:00**。 |
| **自动触发预测** | 新比赛同步入库后，可自动入队常规模型预测；Lindy AI 预测由 Worker 每天北京时间 **14:00** 扫描未来 24 小时未开赛比赛并自动触发。 |
| **回调状态管理** | Lindy 预测请求派发成功后进入等待回调状态，不会被误判为失败；派发失败会写入明确错误；回调入口兼容 URL 查询参数与请求正文追踪字段。 |
| **自动判定命中** | 赛果更新后，系统自动触发评分，判定胜平负、让球胜平负、大小球、比分、半全场等维度的命中情况。 |
| **预测对照复核** | 管理后台可直接读取结构化预测结果，运营人员可选择式修正五类预测内容，并触发共识与命中结果重算。 |

## 主要模块

| 模块 | 当前能力 |
| --- | --- |
| **自动化监控** | 提供自动化任务监控接口，支持实时查看同步日志、预测任务状态及全站战绩统计。 |
| **竞彩数据源** | `SportteryAutoSync` 任务支持抓取中国竞彩网数据，包括销售日期、编号、让球盘口等关键信息；默认固定北京时间执行点已覆盖上午补数窗口。 |
| **AI 预测生产线** | 支持 8 个大模型并发预测，只要任一维度（胜平负/让球/大小球/比分/半全场/进球范围）命中即判定为“红单”。 |
| **Lindy AI 预测接入** | 支持 Lindy Webhook 触发、等待回调、结果落库、结构化解析和任务统计。自动触发时间为北京时间 14:00，预测结果预计在 14:00 后随 Lindy 回调陆续生成。 |
| **命中判定系统** | `scorecard-update` 与 `review-generator` 协同工作，实现比赛维度（共识命中）与模型维度（个人命中）的双重统计。 |
| **预测历史与对照 API** | `GET /matches/prediction-history` 提供最近 7 天的比赛预测历史数据，供前端展示。`GET /admin/prediction-comparisons` 提供管理后台预测对照列表、结构化预测结果及人工复核能力。 |
| **自建 AI 预测接入** | 飞鲸 / Bet007 自建 AI 预测服务按接口 `key` 拉取预测数据，支持 gzip/JSON 解析、5 分钟缓存、外部比赛 ID 优先匹配、本地队名和开赛时间兜底匹配。 |

## 关键环境变量配置

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SPORTTERY_DAILY_SYNC_CRON` | `0 19,21,2,3,7,16 * * *;30 2 * * *` | 竞彩赛程同步定时表达式。服务器按 UTC 执行，对应北京时间 03:00、05:00、10:00、10:30、11:00、15:00、24:00；多个 cron 使用英文分号分隔。 |
| `SPORTTERY_RESULT_CHECK_CRON` | `0 19,21,2,3,7,16 * * *;30 2 * * *` | 竞彩赛果检查定时表达式。服务器按 UTC 执行，对应北京时间 03:00、05:00、10:00、10:30、11:00、15:00、24:00；多个 cron 使用英文分号分隔。 |
| `SPORTTERY_SYNC_DAYS_AHEAD` | `3` | 向后同步的天数。 |
| `SPORTTERY_AUTO_ENQUEUE_PREDICTIONS` | `true` | 是否自动将新比赛入队 AI 预测。 |
| `LINDY_PREDICTION_SCAN_CRON` | `0 6 * * *` | Lindy AI 自动触发扫描定时表达式。服务器按 UTC 执行，对应北京时间 14:00。 |
| `FEIJING_AI_URL` / `BET007_AI_URL` | `http://interface.titan007.com/football/ai.aspx` | 自建 AI 预测接口地址，可按供应商实际地址覆盖。 |
| `FEIJING_AI_KEY` / `BET007_AI_KEY` | `880306AAC9A249EA` | 自建 AI 预测接口密钥，请优先在生产环境变量中维护。 |

> **注意**：如果生产环境仍使用单个 cron 字符串，半点任务无法与整点任务共用同一个标准 cron 表达式完整表达。建议使用 `*_CRONS` 多表达式配置；Worker 会在注册新 repeatable job 前清理同名旧任务，避免历史任务残留导致重复执行。

## Lindy AI 预测链路

Lindy AI 预测链路分为“任务创建、Webhook 派发、等待回调、回调解析、结构化落库、统计展示”六个阶段。任务派发成功后会写入 `requestSentAt` 并保持等待回调状态；只有 Lindy 明确返回错误、Webhook 派发失败或任务执行异常时，才会进入失败状态。

| 阶段 | 说明 |
| --- | --- |
| **自动扫描** | 每天北京时间 14:00 扫描未来 24 小时未开赛比赛，避免按赛前 7 小时滚动触发造成用户预期不明确。 |
| **手动触发** | 管理后台可对单场比赛手动触发 Lindy 预测；重跑时会清理旧错误并重新进入等待回调状态。 |
| **回调兼容** | 回调接口同时兼容查询参数和请求正文中的 `taskId`、`trackingId`、`runId` 等追踪字段，提高 Lindy 返回结果落库成功率。 |
| **结构化解析** | 优先读取 Lindy 返回的结构化字段；若字段缺失，则从原始文本中兜底提取胜平负、让球胜平负、大小球、比分和半全场。 |

## 预测对照结构化复核

预测对照 API 会返回每个模型的结构化预测内容，管理后台不再要求运营人员编辑原始 Markdown。人工修正时，系统保存结构化预测并重新计算共识与命中结果。

| 字段 | 说明 |
| --- | --- |
| `resultPrediction` | 胜平负预测，取值为主胜、平、客胜等标准方向。 |
| `handicapPrediction` | 让球胜平负预测，结合比赛让球盘口进行评估。 |
| `totalGoalsPrediction` | 大小球预测，支持大球、小球、走水或未选择。 |
| `scorePrediction` | 比分预测，格式为 `主队进球:客队进球`。 |
| `halfFullPrediction` | 半全场预测，格式为 `半场方向/全场方向`。 |

## 部署与运维

### 自动部署

代码推送到 `main` 分支后，GitHub Actions 会自动部署到生产服务器。部署脚本 `deploy/production/deploy-backend.sh` 会自动补全缺失的竞彩环境变量，并将旧的 `0 0,6,12 * * *` 或 `*/10 * * * *` 频次迁移为新的固定北京时间执行点。Worker 启动时会在注册新定时任务前清理同名旧 repeatable job，避免生产 Redis 中残留的旧任务继续执行。

### 手动补全环境变量

若需手动在服务器上配置最新环境变量，可执行：

```bash
bash /home/ubuntu/apps/ai-worldcup-backend/deploy/production/patch-env-sporttery.sh
```

## Worker 任务说明

| 队列名称 | 作用 |
| --- | --- |
| `sporttery-auto-sync` | **核心闭环入口**：同步竞彩数据、赛果，并触发后续预测与评分。 |
| `prediction-generator` | 生成 AI 多模型预测，计算共识。 |
| `lindy-prediction` | 派发 Lindy Webhook、等待回调并保存结构化预测结果。 |
| `scorecard-update` | 对已完赛比赛进行模型命中判定，更新模型战绩。 |
| `review-generator` | 生成赛后结构化复盘内容。 |

## 比赛统计口径约定

| 口径 | 定义 |
| --- | --- |
| **红单（红）** | 一场比赛中，只要 8 个模型中有任意一个模型的任意维度预测正确，该场比赛即计为“红”。 |
| **黑单（黑）** | 一场比赛中，所有模型的所有维度均预测错误。 |
| **模型战绩** | 模型详情页显示“近 N 红 M”，其中 N 为总评估场数，M 为 `anyHit` 场数。 |
| **Lindy 等待回调** | Webhook 已派发但尚未收到 Lindy 回调时，属于等待状态，不计为失败。 |

## Roadmap / 未来增强

以下是 Worldcup 项目后端服务未来计划增强的功能点。

1. **详情页综合研判数据重构**：深度优化“AI 综合研判”的数据来源与处理逻辑。消除当前硬编码的默认概率，使其基于有效模型数据进行透明化计算，并提供数据质量或置信度指标。
2. **未解锁模型卡片近 N 中 M 战绩展示**：在未解锁状态下，模型页卡将显示模型的“近 N 中 M”战绩数据，以增强用户吸引力并促进解锁，同时确保不泄露具体预测方向。
3. **Lindy 结果解析持续评估**：持续积累 Lindy 回调样本，对结构化字段、中文标签和自然语言兜底解析规则进行迭代，进一步降低误读率。
